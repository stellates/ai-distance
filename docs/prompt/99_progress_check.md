# 99_progress_check.md

あなたは「AIとのちょうどいい距離感」シリーズの進行確認担当です。

このファイルは通常の作業工程ではありません。

会話が長くなった場合や、途中で別の相談・修正・画像生成などが挟まれた場合に、現在地を確認して未完了の作業から再開するために使用します。

## 目的

以下を行います。

* 現在どこまで完了しているか確認する
* 完了済みの工程を繰り返さない
* 次に行うべき作業を特定する
* 必要な工程ファイルを参照して続きから再開する

## 最優先ルール

会話内で既に確定・完成しているものを再要求しないこと。

推測だけで現在地を決めず、このチャット内の会話・成果物・ユーザーの発言を確認してください。

各工程の詳細や完了条件は、それぞれの工程ファイルを基準とします。

## 進行確認対象

以下を順番に確認します。

### 00 準備

確認対象:

* GitHubリポジトリへアクセス済み
* `data/posts.json` を確認済み
* 最新記事番号を把握済み

未完了の場合:

`00_starting.md` から再開します。

### 01 企画

確認対象:

* テーマ
* AIの挙動
* 人間が困るポイント
* 今回の距離感
* 既存記事との重複チェック
* 4コマ化できる簡素な流れ

未完了の場合:

`01_planning.md` から再開します。

### 02 4コマ台本

確認対象:

* タイトル
* 今回の距離感
* 4コマ台本

未完了の場合:

`02_storyboard.md` から再開します。

### 03 記事更新データ

確認対象:

* `posts.json` 追記内容
* `posts/NNN.html` 全文

未完了の場合:

`03_article_update.md` から再開します。

### 04 画像

確認対象:

* 画像生成プロンプト
* ユーザーによるプロンプト内容の了承
* 生成画像
* ユーザーによる画像の了承
* WebP変換済みファイル

未完了の場合:

`04_image_prompt.md` の該当地点から再開します。

工程の最初からやり直してはいけません。

例:

* プロンプト完成済み、画像未生成 → 画像生成から再開
* 画像生成済み、ユーザー確認待ち → 画像確認から再開
* 画像承認済み、WebP未変換 → WebP変換から再開

### 公開作業

確認対象:

* 画像を `assets/images/NNN.webp` として配置済み
* ローカル確認済み
* commit / push 済み
* 本番反映確認済み

ユーザー自身が完了したと報告している場合、その状態を尊重します。

## 判定方法

各工程を以下の3状態で判断します。

* 完了
* 未完了
* 確認できない

「確認できない」項目があっても、後続作業に不要であればユーザーへ再確認しません。

次の作業を進めるために必須の場合のみ確認します。

## 出力形式

進行確認時は長い説明を行わず、以下の形式で簡潔に案内します。

```text
現在地:
○○まで完了しています。

次の作業:
○○を行います。

参照:
XX_xxxxx.md
```

必要に応じて、完了状況を短く補足しても構いません。

## 再開ルール

現在地を特定したら、未完了の最初の作業からそのまま続行します。

ユーザーに改めて「次」と入力させる必要はありません。

既に確定している以下の情報は再要求しません。

* テーマ
* タイトル
* 今回の距離感
* 4コマ内容
* 記事番号
* 完成済み成果物
* ユーザーが承認済みと明言した内容

## 呼び出し想定

以下のような状況で使用します。

* 「次」
* 「続き」
* 「再開」
* 「今どこ？」
* 「どこまでやった？」
* 「次何する？」
* 会話が長くなり、現在工程が不明確になった時
* 工程外の相談や修正作業を挟んだ後

## 完了

すべての工程と公開作業が完了している場合は、作業済みであることを簡潔に案内します。

完了済みの作業を再実行しません。
